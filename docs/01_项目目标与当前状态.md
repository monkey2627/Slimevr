# 项目目标与当前状态

## 核心目标

使用五个 IMU 实时驱动 Unity Humanoid Avatar：

```text
Tracker 固件 → SlimeVR Server → SolarXR → mobileposer.realtime.run
→ MobilePose → ws://127.0.0.1:21200 → Unity Avatar
```

| SlimeVR BodyPart | MobilePose label | 实际位置 |
|---|---|---|
| LEFT_LOWER_ARM | `lw` | 左手腕/前臂 |
| RIGHT_LOWER_ARM | `rw` | 右手腕/前臂 |
| LEFT_FOOT | `ls` | 左脚踝上方，作为 shank 输入 |
| RIGHT_FOOT | `rs` | 右脚踝上方，作为 shank 输入 |
| WAIST | `waist` | 腰部 |

布局名为 `wrists_shanks_waist`。BodyPart 是路由标签，不代表训练数据中的精确安装点。

## 已完成

- SolarXR 自动识别布局与断线重连。
- 本地 SlimeVR 输出 reference-adjusted rotation 和 acceleration。
- MobilePose 实时推理、30 FPS、45 帧历史窗口初始化。
- Web 可视化、录制、回放、精确 feature/SMPL 输出记录。
- Python 到 Unity WebSocket 与 Humanoid 重定向。
- 可选接触、地面、anchor、关节限位和膝盖保护。
- SlimeVR Server、native bindings、GUI 和 Electron 软件可本地构建。

## 当前实时决策

实时主流程固定使用 `referenceAdjustedLinearAcceleration`。Python 不再要求运动 150 帧拟合 heading，只采集自然直立姿态初始化历史窗口。`--calibration-frames` 仅为旧命令兼容保留，推荐为 `0`。

## 当前主要瓶颈

- 五 IMU 无法直接观测髋、膝、肩、肘。
- 脚踝实际安装点与训练位置/分布存在差异。
- 微调动作和样本数量不足。
- 跪、躺、手撑地等姿态具有强多解性。
- 模型固有约 4 帧、约 133 ms 延迟。

Python heading 与 Server adjusted 的同帧输出几乎一致，说明 heading 对齐不是当前明显误差的主要来源。
