# 目录结构与迁移

文档和命令统一以项目根目录 `<root>` 为基准。新代码和文档使用相对路径，不写死本机盘符。

## 核心目录

| 路径 | 用途 | 保留策略 |
|---|---|---|
| `mobileposer/` | 模型、实时输入、推理、录制、回放、Web 可视化 | 核心代码 |
| `SlimeVR-Server/` | 本地 SlimeVR、SolarXR 协议、GUI、构建脚本 | 完整保留 |
| `IMUTrack-for-Spine/` | Unity 工程、AvatarScene、PoseSource | 完整保留 |
| `solarxr_protocol/` | Python SolarXR FlatBuffers 绑定 | 核心代码 |
| `data/` | 原始和预处理训练/测试数据 | 全部保留 |
| `results/`、`checkpoints/` | checkpoint 与训练结果 | 全部保留 |
| `recordings/` | 实时录制、回放和报告 | 保留 |
| `docs/` | 当前主文档，连续编号 00–06 | 保留 |

Unity `Library/`、Gradle、pnpm、CMake、Electron 等构建缓存不作为清理目标。

## 项目重命名

若将根目录改为 `motionUse`，代码应继续使用相对路径。Codex 会话通常绑定旧工作区路径；可以在旧路径创建指向新目录的 Windows junction，并在新会话提供 `docs/README.md` 和 `docs/01_项目目标与当前状态.md`。

## 清理规则

- 不删除训练数据、checkpoint、SlimeVR 源码、Unity 源码和构建缓存。
- 仅删除确认不在当前链路使用、且没有独有实验结果的历史文件。
- 删除前后用 `rg` 检查引用。
- 不覆盖用户已有的未提交修改。
